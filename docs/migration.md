# Codexter 配置迁移契约

状态：Windows 本机数据预览、导入、加密备份、幂等和回退已实现并验证。服务接管未实现，也不会在导入时自动进行。
参考旧版本：1.0.13+14，源码提交 13893fa。以实际检测到的源版本为准，不能盲目套用。

## 输入资产与保留条件

| 旧数据 | 必须保留 |
| --- | --- |
| global_config.hive | 当前及未启用的提供方配置、代理、可用偏好；取消桌面后无对应行为的字段保留在兼容归档中 |
| workspaces.hive | UUID、名称、目录、启停、时间字段、autoStart 原值、能力选择、Agent 指令、OpenAI Tunnel ID |
| skills.hive 与 skills/ | 元数据、启停、完整技能目录和辅助文件 |
| downstream_mcps.hive | command/args/env/cwd/url/headers/超时/来源/启停；敏感值转为凭据引用 |
| Cloudflare 文件 | cert.pem、运行凭据、Tunnel ID、域名、路由配置和可复用二进制路径 |
| 系统安全存储 | OpenAI Runtime API Key，经源应用有权访问的机制安全转交 |

## 导入策略

1. 分别识别 codexter 与 codexter-dev，不自动混合。
2. 读取内存快照，迁移前后比较数据库与资产摘要；源发生变化时拒绝提交。
3. 使用 Hive 2.2.3 官方内存 backend 和保留全部字段编号的只读适配器；不创建原库锁或触发恢复。
4. Windows 在原用户会话用 DPAPI 只读解密；完整载荷仅经父子进程私有管道，绝不进入 CLI 输出、日志或普通中间 JSON。
5. 在新数据目录预演导入，校验数量、UUID、文件摘要、字段和值；保留原始兼容归档。
6. 将旧全局提供方转换为默认 TunnelProfile，工作区绑定原活动提供方；未活动配置保留但不启用。
7. 复用原域名与 Tunnel ID，不重新创建隧道、不覆盖 DNS、不重置 UUID。
8. 本次只提交数据，不启动外部客户端。后续服务交接需单独验证，禁止旧新客户端不受控地共同接管同一 Tunnel ID。
9. 提供新配置回退：只允许回退最近一次迁移，配置有后续修改则拒绝覆盖。原数据始终保持只读。

## 实现与使用

- TUI：迁移 → 选择来源 → 预览 → 确认备份并导入；结果页可以查看工作区或回退。
- CLI：`migration preview/import/rollback`；导入要求预览 fingerprint，阻止确认后源数据变化。
- Hive 原始字节、解码字段、Cloudflare 管理/运行凭据和迁移前配置进入 AES-256-GCM 加密存储。
- 加密主密钥保存在系统凭据库；普通 config.json 仅包含引用。不能只复制数据目录就声称跨机凭据迁移完成。
- 技能与受管二进制逐文件复制并验证 SHA-256；源符号链接或目标目录联接会明确拒绝，不无界跟随。
- 技能元数据沿用旧字面解析，保留 `name: 123` 等名称及原启停关联；入口大小写由源文件系统判断。
- 废弃界面偏好、未知 Hive 字段以及休眠提供方字段仍保留在加密归档中。
- macOS 采用原 Keychain service/account 正常查询，但未在实机验收；Linux 来源凭据迁移明确报未支持。

2026-10-13 实际导入：9 个工作区、2 个下游 MCP、1 个 Cloudflare 配置、8 个源文件。源 Skills 目录及 Hive 均为空。
108 个工作区字段及两个完整 transport JSON 已核对，原数据摘要未变。

## 验收条件

- 工作区数、UUID、Agent 指令及 null/空名单语义一致。
- 技能文件摘要一致，外部关联路径不存在时有明确报告。
- 下游配置不丢参数或认证字段，不把未知字段静默丢弃。
- 原域名与 UUID 保持时公网 URL 不变；OpenAI Tunnel ID 保持。
- 重复导入幂等，冲突必须报告，不能重复生成工作区或隧道。
- 旧数据和凭据可回退；迁移失败不损坏旧服务。
- 跨系统路径须重新映射；外部二进制必须与新系统和架构匹配。

不承诺迁移运行中的命令进程、内存日志或临时截图状态。交接需等待活动任务结束。
系统凭据无法跨系统直接复制；必须通过受控迁移或重新授权解决，不能宣称自动无损。
