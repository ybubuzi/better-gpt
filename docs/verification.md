# 验证记录

当前开发与手工协议验证环境：Windows x64、Node.js 24、PowerShell 7。此文件记录实现范围和验证边界，不保存个人项目名、工作区ID、进程ID、隧道域名或服务器地址。

## 已验证

- 2026-10-14新增配置诊断：记录名义与物理配置路径、存储标识、客户端/后台PID、工作区完整名称、UUID、绝对目录和绑定；TUI d及CLI diagnostics查看。
- Windows打包宿主实测名义AppData配置文件被重定向至包LocalCache，目录realpath仍可保持名义路径；旧名义路径管道会跨存储混连。新版按实际写入标识隔离控制通道，并在绑定前验证物理文件。
- 隔离后台实际加载名为“测试”的工作区并成功绑定；不存在UUID的绑定错误包含UUID和配置路径，前后台日志按同一requestId记录请求与未找到结果。
- 实际TUI d诊断页、Home/End翻页、绑定页内d快捷入口及q退出通过；用户在普通PowerShell重新启动后确认诊断两侧都包含其“测试”工作区。该普通终端反馈与隔离操作验证分别记录，不把Codex容器的配置列表当作用户终端列表。

- `npm run typecheck` 与 `npm run build` 完成；TUI和CLI从源码编译成功。
- Codexter的14个基础工具在隔离配置中通过MCP工具发现和协议调用；包括文件读写、图片、检索、Skills、下游MCP、命令会话和摘要。
- 原Cloudflare入口与一个自建SSH入口同时运行；每个入口只允许绑定的工作区。两个入口的MCP路径保持 `/{workspace UUID}/mcp`，非绑定工作区返回404。
- 自建SSH公网入口上的文件操作、检索、命令执行成功；SSH反向转发只监听服务器回环端口。
- 隧道范围控制：暂停共享入口中的一个工作区后，该项目公网返回404、其他绑定项目和本地MCP仍可用；暂停最后一个绑定项目后才停止共享连接器。
- 按提供方启动不会停止其他提供方；全部启动会恢复先前单独暂停的已启用项目。TUI侧栏可搜索工作区并按项目菜单控制，按渠道菜单分组操作。
- TUI退出不会停止后台MCP和隧道。实际操作了项目暂停、渠道菜单和全部启动；状态颜色随后台状态更新。
- frpc下载使用固定版本和SHA256校验；本机安全软件拦截Windows发行包解压，没有绕过该拦截。frp运行器已编译，但该Windows主机的frp端到端连接未经验证。

- 类型检查和工作区构建完成；`npm pack` 生成仅21个文件、约200KB的tarball，未包含日志、工作目录、用户配置或本机二进制。
- 在源码仓库外的独立临时目录安装tarball，版本/帮助、初始化、新增工作区和独立后台启停通过；运行时不依赖未发布的内部workspace包。
- 安装包本地MCP发现15项工具，工作区身份、文件变更及搜索worker调用通过。sharp和系统keyring原生模块可加载。
- 安装包在原生终端打开TUI、切换Skills模块并按q退出；退出后后台仍运行。前后台配置路径和指纹一致。

- 最终tarball独立安装后`npm audit --omit=dev`为0项漏洞；移除通用代理组件的PAC/FTP链。HTTP及SOCKS5代理分别请求HTTP和HTTPS目标均返回200。
